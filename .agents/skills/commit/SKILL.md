# Commit

Use a component-scoped type and a 50-column title. The format is space
separated, not `type(scope):` punctuation.

```
<component/feature> <type> <summary>

[optional explanation paragraph]

- change or reason
- change or reason
```

## Title

- Maximum 50 characters, imperative mood, lowercase after the type, no trailing
  period.
- `<component/feature>` names the touched area. Prefer existing names: `match`,
  `match_setup`, `home`, `manager_link`, `tournament`, layers `domain`, `data`,
  `core`, `shared`, app-wide `runout`, and `test` for test-only infrastructure.
- When tests accompany a feature, use the feature component, not `test`.
- Verify the width before committing: `echo -n "$title" | wc -c`.

## Types

Pick the first type that applies:

1. `FIX` — bug fix.
2. `ENH` — functional change, feature, performance, tests, CI.
3. `MNT` — refactor, rename, remove, dependency or tooling upkeep.
4. `DOC` — documentation only.
5. `STY` — formatting only, no meaning change.

Mark a breaking change with `!` after the type: `match ENH! rename keepsTurn`.

## Body

- Use `-` bullets, one change or reason per bullet.
- Add a short explanation paragraph before the bullets only when the reason is
  not obvious from the summary.
- Describe what changed and why, not a file-by-file inventory.
- Never add `Co-authored-by`, `Generated by`, or any other attribution.
- Keep the message concise but descriptive; no emoji or AI watermarks.

## Workflow

1. Inspect `git status --short` and `git diff`; group related files into one
   logical change. Split unrelated changes into separate commits.
2. Choose the component from the touched area and the type by priority.
3. Stage explicit paths, then review `git diff --cached`.
4. Check the title width and commit with a heredoc so the body keeps its blank
   line and bullets:

```bash
git add <paths>
git commit -F - <<'EOF'
match FIX isOpeningBreak on the break only

The flag should only be set on the very first turn only.

- reset after player scores (keepsTurn == true) or end the visit
- add assert that player can't score upon break foul
- fix comment
- add tests
EOF
```

## Examples

```
match_setup ENH responsive MatchConfigPanel

- separate wide and narrow layout
- crossaxisalignment start for the wide layout
- set fixed selectors size
- use padding to center the text
```

```
shared MNT remove unused confirm dialog option

The callback is never invoked.

- delete the option and its test
```
